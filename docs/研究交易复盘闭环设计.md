# Dean A股 Agent 研究交易复盘闭环设计

设计版本：1.0；对应需求规格：1.2；日期：2026年9月16日。

本文将Dean最新要求落实为四个衔接阶段：按自选股定期采集，采集完成后研究并更新买卖计划，交易时段每30分钟决策，每日复盘前24小时并反馈到后续研究。重点是确保每次决策可回答“当时知道哪些数据、依据哪版计划、实际执行了什么”。

这是完整目标设计，不能据此认定每项均已部署。2026-09-16已完成0.2本机研究与模拟闭环；实际实现范围、测试与缺口见README和VALIDATION.md。真实账户仍未连接。既有初始预算10万元、盈利再投资、分档利润提取规则保持有效。

## 1 已确认要求与建议默认值

Dean确认研究对象为自己选定的股票；数据抓取可以每日一次或每12小时一次；抓取完成后研究并更新买入与卖出点位；每个30分钟Slot查看盘面，决定买入、卖出或不动；每日复盘此前24小时，复盘结果进入研究输入。

建议先采用每天08:00与20:00两次深度采集，每日19:30复盘，全部使用Asia/Shanghai。这些钟点、12小时档、计划有效期和超时容差是可配置默认值，不表示Dean已经额外确认。若改为每日一次，四阶段及数据契约不变。

深度采集覆盖公告正文、公司报告、授权券商研报、相关新闻全文、财务与估值、完整日线和公司行为；Slot额外刷新即时行情、账户、挂单、成交回报及重大新事件状态。因此“每12小时抓取一次研究资料”不等于“盘中使用12小时前的行情”。

对每只自选股独立维护研究档案、计划版本与复盘状态；交易资金由一个账户级协调器统一管理。停止关注某只股票不能停止监控其尚未清空的持仓、未终结订单或待对账事项。

## 2 四个阶段如何衔接

```text
采集批次 → 校验与整理 → 冻结研究快照 → 股票研究 → 验证并发布交易计划
                                                  ↓
当时有效的计划 + 新行情 + 账户及挂单 + 事件检查 → Slot决策 → 风控 → 订单与成交
       ↑                                                                       ↓
       └──── 下一次研究 ← 内部复盘记忆 ← 前24小时的决策 订单 成交 不动记录及结果 ────┘
```

深度采集和研究用完成事件衔接，不能仅靠“08:00抓取、08:05研究”的固定等待。某只股票的数据已经准备好，可以开始该股研究；其他股票的失败不必阻塞整批，但市场和行业公共数据缺失必须反映到依赖它们的股票。

没有新增材料时也要检查已有计划是否到期、事件是否解除、复盘是否新增；允许复用未失效观点，但不能无审阅延长买卖计划。模型额度不足时，资料继续保存，研究标为延迟。

## 3 采集批次与不可变快照

每次采集生成`batch_id`，每个来源和股票分别保存起止时间、查询范围、分页进度、预期覆盖、实际数量、错误和内容版本。空结果、读取失败、分页截断、仅有标题和全文成功必须是不同状态。

批次状态为`CREATED → FETCHING → PROCESSING → READY / PARTIAL / FAILED`。READY表示满足该任务已声明的覆盖要求，不表示互联网上不存在其他资料；研究仍需记录授权范围和未覆盖来源。PARTIAL允许生成说明缺口的研究，但不能自动成为可交易计划。

采集完成后冻结`snapshot_id`，记录截止时刻、来源检查、完整文档版本清单、结构化事实版本、公司行为版本、策略版本、已生成复盘版本及清单哈希。原始清单必须可枚举，不能仅保存一个无法还原内容的哈希。

一次研究只使用同一快照中的版本。在研究执行期间新到达的数据进入下一快照，不能悄悄改变当前输入；若新数据属于重大风险，可取消当前计划发布并触发重新研究。历史快照和已完成研究不被覆写。

## 4 数据如何分类和标记

将外部事实、外部观点、内部判断、交易事实和复盘经验分开保存。分类不是只靠文件夹，而是写入结构化字段并参与检索过滤。

| 数据层 | 内容 | 使用方式 |
| --- | --- | --- |
| 原始材料 | PDF、网页、新闻、接口响应 | 保存原文、来源、哈希和版本，作为最终证据 |
| 已验证事实 | 财务、行情、正式事件、公司行为 | 通过SQL按期间、单位和版本读取，参与确定性计算 |
| 外部观点 | 券商预测、目标价、管理层展望 | 作为观点比较，不能当成已实现经营事实 |
| 内部研究与计划 | 投资论点、证伪条件、买卖区间 | 通过版本和有效期供Slot使用，不能自我充当证据 |
| 执行事实 | 每次决策、风控、订单、成交、费用 | 以账户及执行回报为准，研究建议不等于成交 |
| 内部复盘 | 错误分类、经验、待验证假设 | 单独进入研究上下文，必须关联原决策与成交 |

每个资料版本至少保存以下字段组：

| 字段组 | 必需标记 |
| --- | --- |
| 身份 | `document_id`、`version_id`、`document_family_id`、`content_hash`、`schema_version` |
| 关联 | `issuer_id`、包含交易所的`instrument_ids`、行业及分类版本、关联理由 |
| 来源 | `source_id`、`source_url`、`source_type`、作者机构、原始发布者、原文定位 |
| 内容性质 | `document_type`、`claim_type`为FACT或OPINION或FORECAST或INTERNAL_LESSON |
| 时间 | `event_at`、`published_at`、`first_seen_at`、`ready_at`、`reference_period`、`time_precision` |
| 修订与去重 | `supersedes_version_id`、`revision_known_at`、`event_cluster_id` |
| 质量 | `extraction_status`、`validation_status`、`coverage_status`、冲突与OCR标记 |
| 使用条件 | `license_scope`、`cloud_allowed`、适用任务、失效条件或下一核实时间 |
| 关联链 | `batch_id`、事实引用的`chunk_ids`、使用本资料的快照和研究ID |

事实表还必须保存指标名、值、单位、币种、合并或母公司口径、报告期、累计或单季度口径、是否预测、原文表头与脚注。上市公司和子公司的指标不能混算，同名指标不能只凭文本相似度合并。

多只股票共用的行业、市场或供应链事件采用一份原文加多对多关联，不复制成多条独立证据。媒体转载通过`event_cluster_id`合并；同一财报摘要和全文也不能增加“独立证据数量”。模型建议的实体关联先标为待验证，不能直接混入另一只股票的事实表。

## 5 让时间和版本成为硬约束

`event_at`表示事情发生时间，`published_at`表示来源发布的时间，`first_seen_at`表示本系统首次取得该版本的时间，`ready_at`表示该资料已完成解析、校验并提交为可使用记录的时间。它们不等价。

研究快照必须固定`as_of`，用于执行的记录须满足：已知发布时间不晚于截止点，首次获取和对应可用状态提交也不晚于截止点。只有日期的发布时间标明精度，不能编造具体时刻；可用时间按首次观察和处理完成时间保守确定，未来日期、时间冲突进入复核。各类资料的READY标准不同，标题不能达到“正文已读”，未验证表格不能达到“可自动计算财务指标”。

例如：公告09:55发布、10:01抓到、10:04解析完成，10:00的Slot不能使用其正文；下一Slot可以使用。10:00决策不能因10:04后来获知的信息被改写。次日才抓到的旧公告也不能伪装成昨天系统已经掌握。

修订采用追加版本和有时间戳的状态事件。当前研究使用截止点之前已经知道的最新有效版本；历史复盘使用当时知道的旧版本，并单独标注后来修订。禁止用无时间维度的`is_latest`或`is_valid`覆盖掉历史选择依据。相同URL的内容也应按政策定期复查哈希。

披露事实可能长期有效，新闻热度可能短期消退，交易计划可能只有数小时有效，不能给所有资料统一设置“超过7天即过期”。未解决的重大风险必须持续进入必读清单，直至正式解除。

## 6 研究时如何检索和组装资料

每只股票生成独立的`research_packet`，按以下顺序装配：

1. 固定规则、该股档案、已有论点与证伪条件，以及当前账户相关敞口。
2. SQL读取已验证的财务、估值、价格特征、行业基准及公司行为版本；不让向量搜索代替数值计算。
3. 完整列出上次成功研究之后的新增或修订公告、尚未解决的重大风险和变化清单。这部分不受Top K截断。
4. 按股票、时点、快照成员、内容类型、验证状态和云端权限过滤，再执行中文关键词加语义向量检索，重排并选择相关原文。
5. 同时检索支持与反对当前论点的证据；财务表格附完整表头、单位和上下文，必要时返回父章节或整页。
6. 单列最近24小时复盘及仍有效的历史教训，标记为内部经验；附其支持的决策与成交引用。
7. 输出来源覆盖、缺失资料、冲突、排除理由和证据清单，冻结资料包与哈希。

语义向量的作用是发现相关材料，最终引用回到原始版本和页码。嵌入模型、切块方法、分词、重排和查询版本都要保存；换模型或重建索引不改变原始资料ID。当前原型只有FTS5，语义向量属于待实现项。

必读清单超过上下文预算时，先拆分有限子任务逐份审阅、记录完成状态，再合并结果；不能静默丢弃后半部分，也不能仅依赖模型生成的总摘要放行交易。关键公告未读完时保留缺口并阻止新增风险。

外部资料和内部复盘使用不同索引范围。即使共享一个数据库，检索结果也必须保留类型；不能把“昨天AI判断公司前景良好”当成“今天再次找到了一份利好证据”。有引用只代表可追溯，还需核实数字、表头、期间和推断是否成立。

## 7 研究结果如何成为买卖计划

每次研究输出新的`research_id`和每股`plan_id`，通过验证后才成为ACTIVE。一个股票可以保存多版历史计划，但相同策略和账户范围在同一时点最多有一版有效计划。

买入和卖出点位应表达为“价格区间加触发条件”，并标明计算依据。至少包含买入区间、触发确认、追价限制、减仓区间、退出条件、止损参考、数量或仓位上限、有效期、公司行为版本和证据引用。未持仓的股票可以有买入计划；已有持仓需要退出安排；数据不足时允许只有NO_ENTRY计划，不能为了填字段而编造点位。

财务与估值方法、技术计算、价位推导公式及参数应可回放；模型提出候选论点与条件，程序核对计算、数值关系、资金和交易规则。现有v0评分本身不能推导出所有买卖点位，必须补充并验证价位生成方法后才激活可交易计划。

价位统一用人民币和实际可下单的未复权价格表达。研究使用复权序列时须保存复权快照及到实际价格的转换依据；除权除息、拆合股或转换依据改变时使旧计划失效并重算。止损是决策触发条件，不是保证成交的价格。

计划字段至少包括：`plan_id`、`instrument_id`、`account_scope`、`research_id`、`snapshot_id`、`strategy_version`、`generated_at`、`activated_at`、`valid_from`、`valid_until`、`price_basis`、`corporate_action_version`、买卖区间及触发条件、规模限制、证据与否决条件、`validation_result`。

`valid_from`不得早于实际验证和激活时刻。计划状态为`DRAFT → VALIDATED → ACTIVE → SUPERSEDED / EXPIRED / INVALIDATED`；失败草稿不能覆盖有效旧计划。替换用事务完成，并保存激活、撤销和过期事件，不修改既有Slot绑定的计划。

默认建议计划最长有效12小时，重大新信息可提前使它失效。旧计划过期且新计划未完成时，暂停新增风险；持仓仍按独立、有效的确定性风险规则处理，不能把“缺研究”误当成“没有风险”。

## 8 每30分钟的Slot如何决策

Slot是一次有限的组合决策任务，而不是必须交易的信号。建议默认使用交易日09:30、10:00、10:30、11:00、13:00、13:30、14:00、14:30八个启动点，11:30和15:00作为观察或对账点。该时间表避开默认模型运行结束后已休市的边界，实际还须依据对应交易所日历、交易阶段和停牌状态校验。开盘Slot使用开盘后新快照，不能假定刚开盘已经存在完整30分钟K线。

每个Slot保存计划启动时刻、实际开始时刻、行情与账户截点和决策截止时间。超过期限的任务标为MISSED或EXPIRED，恢复运行时不补下旧订单。30分钟是策略决策频率，成交回报和硬风控监控的处理频率可以更高；若没有持续保护机制，就不能声称止损会在两个Slot之间即时执行。

输入包括当时已激活的每股计划、新行情和已完成K线、实际持仓及可卖数量、现金和预留、未终结订单、累计已执行计划数量、最新事件状态。当前计划还未评估的新重大事件必须触发复核；Slot不能自行修改长期研究论点或延长计划有效期来为交易找理由。

输出按股记录`BUY / SELL / HOLD`及理由；另有`BLOCKED / MISSED / ERROR`等执行状态。例如“想卖出但可卖数量不足”应记录SELL意图和BLOCKED原因，不能记成主动看好而HOLD。

所有股票先形成候选，再由账户级协调器统一检查总资金、单股、行业、提取预留、当日新增次数和风险预算。不能让多只股票各自读取同一份可用现金后同时花掉。批次候选排序规则必须确定；拒绝某笔交易时保留候选和拒绝原因。

执行前重新读取行情、账户和风险事件并核对计划仍有效；检查通过后使用数据库事务预留资金并生成唯一订单意图。每个Slot每股最多一个有效净意图；多个Slot也要遵守同一计划的目标仓位、总数量与未成交预留，不能每半小时重复买足一遍。撤单重报作为同一意图的执行尝试记录，不等于新决策。

订单状态、未知回报、部分成交、撤单、费用、滑点、停牌和数量规则按完整需求处理；行情不足或订单状态未知不能“猜测成功后重试”。实盘执行需另行接入并授权，第一阶段使用独立模拟账本。

## 9 每日24小时复盘如何回到研究

建议每天19:30固定以北京时间`[昨日19:30, 今日19:30)`为窗口，保存明确起止时间；以计划截止点计算，而不是用任务实际延迟结束的时刻滑动窗口。周末仍可生成“无交易”及资料/运行复盘。失败后补处理缺失窗口，不把48小时合并后仍标为24小时。

复盘至少读取：窗口内每个BUY、SELL、HOLD与阻断决策，当时的快照、计划、行情和账户版本，实际订单及成交回报、费用与持仓变化，以及相关策略版本。窗口外创建但窗口内成交的订单也纳入，按各自事件时间归属。尚未平仓的交易只给阶段评价，不能计成最终胜率。

先用程序计算执行差异、已实现和未实现损益、费用、资金占用与现金流调整；利润提取单列为资金流，不计入交易亏损。再由模型解释：原论点是否得到支持，价格条件是否实际满足，未成交原因是什么，存在数据、研究、执行还是系统错误。评价决策质量要使用当时可得信息，后来的价格只作为结果观察，不能以事后上涨证明当时必然应该买入。

每条复盘结论保存`review_id`、`window_start/end`、`instrument_id`、`decision_ids`、`order_ids`、`fill_ids`、`plan_ids`、`snapshot_ids`、问题类型、证据、适用条件、失效条件、首次生成及版本、是否待验证。晚到的成交回报生成复盘修订版本；旧版本仍保留，不能把修订时间回填到旧研究。

复盘拆成执行事实、内部经验和策略改进假设三部分。经验可以提示下一次研究关注“汇兑与扣非分化”或“追价后成交偏离”；调整止损比例、评分权重、资金上限等必须生成版本化策略提案并经独立验证，不能凭一天盈亏自动修改规则。

每天20:00研究只读取其快照截止前已生成并达到使用状态的复盘。19:30复盘若20:05才完成，20:00冻结的研究不能使用它；进入下一轮或另行生成补充研究。研究生成的计划只影响激活后的Slot。

## 10 表与版本关系

沿用SQLite和原文目录，新增结构化表，复杂查询仍在本机执行。原型的`research.result_json`和`previous_research`不能独自承担完整关系。

| 新增或扩展实体 | 主要关系和约束 |
| --- | --- |
| `collection_batches` 与 `source_checks` | 每来源每股完成状态、完整性、分页和失败 |
| `document_versions` 与 `document_instruments` | 原文修订、证券多对多、发布时间与就绪时间 |
| `facts` 与 `fact_evidence` | 类型化数值、期间单位、合并口径、验证状态及引用 |
| `events` 与 `event_clusters` | 风险未解除状态、影响股票、同源转载合并 |
| `research_snapshots` 与 `snapshot_members` | 不可变清单及哈希；成员指向精确资料版本 |
| `research_runs` 与 `research_findings` | 每股研究、策略版本、输入快照、观点与证伪条件 |
| `trade_plans` 与 `plan_status_events` | 买卖条件、实际激活时间、失效和替换历史 |
| `slot_runs` 与 `slot_decisions` | 唯一Slot，每股行动、计划与快照、被否决原因 |
| `risk_checks` 与 `order_intents` | 账户级事务预留、并发校验、目标数量和去重 |
| `orders` 与 `fills` | 模拟与实盘隔离；执行回报、未知状态、成交费用 |
| `reviews` 与 `review_lessons` | 固定24小时窗口、晚到事件修订、内部经验 |

核心追溯链为：`fill → order → intent → decision → slot → plan → research → snapshot → evidence versions`。复盘引用这条链，再被未来快照作为INTERNAL_LESSON引用，形成有时间方向的反馈；不能让同一轮研究和其后复盘互相成为前置证据。

## 11 发布前必须通过的检查

1. 晚抓到的旧公告不进入早于首次可得时刻的快照；未解析完成的正文不参与计算。
2. 修订财报同时保留旧版，新研究使用截止前有效版本，历史决策能还原旧版。
3. 证券名称相近、同公司多证券和行业材料均按显式关联，不串到错误股票。
4. 必读风险事件不因Top K或上下文截断而丢失；未读完阻止新增风险。
5. 来源失败不能当作没有事件，标题不能当作已读全文，推测不能当作事实。
6. 研究尚在运行或新计划未激活时，Slot无法提前使用它；过期或撤销计划不能下单。
7. 研究过程中到达的新材料不改变已冻结快照；关键变化可取消发布并重新研究。
8. 同Slot重启不重复下单；后续Slot计算已有持仓、未成交数量和目标剩余额度。
9. 多股并发候选通过账户级预留，合计不能透支；利润提取预留不得用于买入。
10. 除权除息后旧价位失效；复权价与实际下单价不会直接混用。
11. HOLD与被阻断的BUY或SELL分别复盘；未知订单状态不会被重试成两笔订单。
12. 固定24小时窗口不重叠计数，跨窗口订单按事件时间处理，延迟回报追加修订。
13. 复盘不是外部利好证据，也不能用后来行情反写当时计划；未平仓不计算最终胜率。
14. 休市、午休、停牌、启动过晚和模型超时均留下记录，不补下过期意图。

这些是待实现验收要求，不能用现有12项单元测试替代。

## 12 与现有代码的衔接顺序

第一步先补数据模型和时间边界：资料就绪状态、版本、事件、不可变快照、按股票组装研究包。为原型历史记录保留真实可证明的时间；缺少ready_at的旧记录在迁移时保守标记，不伪造早先已就绪。

第二步把现有`run`拆成独立的collect、research和plan发布阶段；保留一次运行入口用于调试。财务事实未补齐前，研究可产出NO_ENTRY计划和待核实条件，不能生成伪精确价格。

第三步实现Slot、账户级风控与独立模拟订单/成交账本，再实现包含所有行动的24小时复盘和内部经验检索。用历史固定样本与模拟回报验证版本关系、账户预留、并发和晚到数据。

第四步接入正式交易日历和唯一调度入口，开启演示股持续模拟；调度频率与用户最新要求一致，旧“小时研究”入口不再作为目标工作流。完成持续运行验证后，再依据东方证券接口条件单独接入实盘。

0.1兼容命令`run --kind daily_review`仍仅是研究报告标签；0.2新增`review`才读取模拟交易账本。0.2已实现隔离模拟成交和相关测试，实际账户未接入。

交易时段设计参考上交所[交易时段说明](https://english.sse.com.cn/start/trading/schedule/)及[2026年交易规则发布页](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)。上线时需核对适用交易所、板块、规则生效日及日历版本；本设计中的Slot启动点是工程建议。
