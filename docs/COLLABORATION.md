# ThesisTrade：本地登录、个股研究与意见协作

## 第一次打开

1. 打开 http://127.0.0.1:8765/ ，页面会进入“首次设置”。
2. 分别填写 Admin 和 Guest 的密码，每个至少12个字符，两者必须不同；再次输入确认。
3. 点击“完成设置”，选择 Admin，输入刚才设置的密码登录。
4. 首页列出全部自选股。点击股票名称进入其独立页面，例如 `/stocks/sz000333`。

这一步不需要 API Key。请在页面或本机终端输入密码，不要写进 config.json、文档或代码仓库。首次设置完成后入口自动关闭，登录状态保留12小时。退出或修改密码会使对应会话失效，关闭网页不暂停后台。

## 两个账号能做什么

| 操作 | Admin | Guest |
| --- | --- | --- |
| 查看自选股、研究、模拟持仓与完整交易记录 | 可以 | 可以 |
| 首页/个股右侧提交意见 | 可以 | 可以 |
| 更新研究、补齐资料、检查盘面、更新复盘 | 可以 | 不可以 |
| 修改自选股、自动运行和账号密码 | 可以 | 不可以 |
| 读取意见列表、处理状态和管理员备注 | 可以 | 不可以 |
| 下真实证券订单 | 当前未实现 | 当前未实现 |

两个都是共享账号。昵称可选，用于识别建议来源，不构成个人身份认证。管理员页面位于 `/admin/feedback` 和 `/admin/settings`，服务端同时检查权限；隐藏按钮不是唯一限制。

## 阅读个股页

顶部优先展示当前行动判断、报价时间、买入区间、卖出/止损参考及计划有效期。参考价来自现有策略，只有一个卖出价时不编造区间。下方依次展示当前持仓与已实现收益、最新研究总论、关键证据和触发/失效条件。

研究固定为六个展开维度：经营与增长、现金流与资产负债、估值与价格反映、价格趋势、事件与行业风险、交易触发与失效条件。新研究在同一次模型调用中生成这些分项，引用须通过原文核验。旧报告只将已有判断和底稿放入对应维度，标记为整理结果，不另造事实、不伪称重新分析。缺乏独立分析的维度如实提示，后续定时研究更新。

“还缺什么与下一步”包含限制原因、在等什么、处理方、下一步与解除条件；相应资料成功取得后，失败项会消失。公共资料问题仍可能影响多只股票。历史成交、委托、盘面判断各按30条分页，空记录明确说明，没有成交不展示虚构收益。

## 意见处理

登录用户可以在右栏提交策略、数据、体验或其他建议。股票意见关联提交时正在阅读的研究版本；首页意见讨论整体系统。页面每10秒刷新业务数据，意见输入框保持不动。请求重试带相同提交标识以避免重复保存。

只有 Admin 能查看收件箱，可按股票/状态筛选，标记“待查看 / 处理中 / 已采纳 / 暂不采纳”并写管理员备注。意见不会成为公开评论，也不会自动送进研究证据、改变规则或触发交易。“已采纳”仅为处理记录，实际策略修改另行实现和验证。

## 改密或忘记密码

已登录 Admin：进入“设置与运行”底部，选择账号设置新密码；修改自己的密码后需要重新登录。

忘记 Admin 密码：在本机终端运行，按提示输入两次新密码（输入不显示）：

```sh
cd /Users/dean/Documents/Codex/Agents/ashare-agent
./agent reset-password admin
```

重设 Guest 时将末尾改为 `guest`。密码采用带随机盐的 scrypt 散列保存；数据库不存密码原文，会话只存令牌摘要。密码、会话和意见与模拟账本一同保存在 `../ashare-data/agent.sqlite3`；备份也包含这些私有数据。

## 当前运行边界与后续部署

本轮仍只监听 `127.0.0.1`，朋友不能从自己的电脑远程打开这个地址。账号和意见协作功能已经可以在这台 Mac 上验证；GitHub 建仓、Railway 部署和远程访问等 Mac Mini 方案确定后再做。

未来对外部署前需配置 HTTPS、Secure Cookie、明确允许的来源、首次设置的受控入口、私有持久化数据卷及备份，并明确公开研究资料的许可范围。运行数据、订阅登录和券商凭据不能提交到 GitHub；本轮没有创建仓库、发布网站或改动真实券商账户。
