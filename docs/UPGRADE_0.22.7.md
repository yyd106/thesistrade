# 0.22.7：行业研究结果校验、运行日报与组合排队

2026-10-28 用户在研究性能复盘后明确要求“把能优化的，高置信的，优化掉”。本版落实输出与保存约束对齐、部分成果和失败分类、排队与执行时间分列，以及空闲研究边界的组合优先级。历史拒绝以无证据 WAITING 为主，不代表没有任何研究产出。

## 行业输出与保存约束

每条假设的结构化输出明确要求 1–24 条原文证据，假设数量上限与本轮预算一致。没有可引用原文时，在已有 method_coverage 中说明资料缺口，hypotheses 可以为空；不要求模型为了凑数制造证据。

兼容旧的、结构合法的 WAITING + 空 facts 返回，将它记录为研究缺口，不建立或续期假设。非法身份、跨领域、非法方法、坏引文、无证据的 ACTIVE/INVALIDATED/REALIZED 仍失败。原有证据校验、7 日复核、30 日归档、资格和交易门槛保持原语义。

明确区分完成有成果、无合格假设、资料缺口、部分完成和校验失败。同周期重跑保留此前已经保存的假设引用，模型超时或服务停止不会把这些引用从步骤摘要中抹掉。引用并不等于新增或仍然有效的假设；准入继续读取假设本身的状态和证据日期。本版没有实现逐条候选精准重试；同一步骤后续调用仍覆盖其当前结果分类，不能把最终 DONE 解释为所有历史失败候选都已修复。

## 日报

行业内部步骤独立统计，顶层 DONE 不再遮住内部校验错误、模型超时及部分成果。原因只输出固定分类；假设引用、去重数量和资料缺口分列，不导出错误原文。

任务计划至开始的排队时间，与开始至结束的执行时间分列。未开始和未结束的任务按日报生成时点或历史日终截止，单独显示已经等待/执行多久。任务结果为查询时的存储状态，行业步骤按最后更新时间归属日期；可变记录不能重建所有历史尝试。

## 调度

本机研究端在当前研究全部结束后，先启动已到期、正在排队的组合请求，再开下一批普通研究。组合运行期间暂缓会改动研究输入的普通研究、动态研究和复盘任务；行情检查、同步和报告仍走原队列。云端和 standalone 的分派方式保持原有顺序。

不抢占运行中的长批次，也不取消输入快照发布校验。因此本版能消除“空闲后又被新研究抢先”的等待，不能保证已经开始的长批次之内组合立即运行。AI 行业拆分、长批次断点续跑和扩大并行度尚需独立验证，本版不实施。

## 验收与回退

合成回归覆盖输出数量契约、合法资料缺口不入库、不延长旧证据期限、坏证据继续拒绝、部分成果保留、日报截止时点及内部错误可见性、组合优先启动与研究恢复。发布前执行完整 Python 测试和 UI 测试，并用订阅模型验证结构化输出兼容性。

无配置、数据库结构、账户、硬风控、模型或名单变更。先验证云端版本与代码指纹，再停止本机旧服务、保留旧代码并同步已发布代码。需要回退时还原本次合并并恢复旧代码，保留全部数据。部署成功与测试通过只证明工程验收，不证明长期耗时改善或交易收益有效。
