# 升级到 0.15.0

后续补丁见 [升级到 0.15.1](UPGRADE_0.15.1.md)。

0.15.0 解决 2026-09-25 架构评审指出的三类问题：学习回路没有闭合（复盘发现无法变成经过检验的改动，未验证经验却进入了研究输入）、存储与同步随运行时间膨胀、部分交易规则缺失或会在特定时点失效。所有改动都不放宽硬性风控，不改变本金、提取档位和市场范围。

## 改了什么

**研究与复盘的隔离**
- 复盘发现不再进入研究输入。数据、执行、系统类发现登记为工程问题（同类合并计数），研究、观察类发现登记为提案草稿。只有用户批准并上线的研究规则（`strategy_guidance`）才会进入研究模型的输入。
- 研究提示词列出执行端实际检查的条件，禁止把执行端不检查的盘面条件（量能、企稳等）写成买入前提；研究结论按 20 个交易日相对沪深300的表现检验。
- 复盘增加程序一致性检查：执行是否遵守计划区间、计划限制、组合授权和熔断，数据是否晚到，同步、模型、磁盘是否健康。

**可度量与可追溯**
- 模型名称在调用命令中固定（`model_name`；推理强度 `model_reasoning_effort` 也可以固定，目前未固定），每次调用记录实际运行的模型、CLI 版本、提示词哈希、耗时和用量；实际模型与固定配置不一致时拒绝采用结果。
- `build_id` 由代码、策略类设置、模型和已采纳研究规则共同决定，写入研究计划、组合决策、全球计划、复盘和结论记录。
- 结论注册表：每个判断登记后到期由程序打分；四本对照账本（纯规则、加研究资格、加组合决策、规则定仓位）按日并行；机械规则离线回测命令；周度评估报告。
- 资料和结论都未变化时，研究在 `research_reuse_hours` 小时内沿用上次成功结论并重算价位，不调用模型。

**存储与同步**
- 已发送的策略发布包在数据库中只保留哈希标记，不再写 `publication.json` 副本，改写小的 `manifest.json`。
- 小时备份保留最近 6 小时各一份与最近 7 天每天一份（原为 24 份小时备份）。
- 账本同步改为增量：云端记录可变表的变更日志，本机按游标只拉新增和变化的行及其外键依赖。实测稳态每分钟从约 21MB（压缩后约 5.7MB）降到几十 KB。
- 研究只有在某个候选确实变化时才触发组合重判，并只使受影响候选的授权失效。
- 策略发布中的展示数据按分区发送变化部分。
- 复盘上传只发送云端尚未收到的记录。

**交易规则**
- 支持创业板（300、301）与科创板（688、689）：涨跌幅保护 19.5%，科创板买入至少 200 股、卖出遵守 200 股规则。
- 特殊证券改为按名称开头的 ST、*ST 与上市初期的 N、C 前缀，以及名称中的“退”字判断。旧规则只要名称含字母 N 或 C 就拦截，会误拦名称以 TCL 开头这类普通股票。
- 研究计划按账户净值检查最小申报数量的金额是否超过单股上限，超过时只研究不交易（按 10 万元账户，贵州茅台属于这种情况）。
- 全球资产卖出允许使用 4 天内的最近汇率，外汇周末休市时加密货币的止损仍可执行；买入仍要求 1 小时内的汇率。汇率接口失败时沿用最近一次汇率及其原始时间。
- 交易日历改为数据文件 `ashare/data/cn_a_calendar.json`，每年 11 月起提醒录入次年休市安排。

## 兼容性与部署顺序

新协议由云端在 `/health` 和账本响应中公布（`features`），本机只在云端公布后使用，因此：

1. **先部署云端**：合并到 `main`，Railway 自动部署。新云端对旧本机完全兼容。
2. **再更新本机**：同步代码到 `ashare-agent/`，重启服务。首次同步会传一次完整的可变表，之后为增量。

数据库只新增表和触发器，不修改既有表结构；回退到 0.14.0 不需要迁移数据。

## 本机设置

部署本机时写入以下设置（用 `./agent config set`，会校验并留痕）：

| 设置 | 值 | 原因 |
|---|---|---|
| `model_name` | 当前实际运行的模型（2026-09-25 为 `gpt-6-astra`） | 固定模型，避免应用升级悄悄更换 |
| `model_reasoning_effort` | 不设置（null） | CLI 输出抬头的 `reasoning effort: none` 表示“未指定，由服务端按默认值处理”，不是可写入的取值：`gpt-6-astra` 只接受 low、medium、high、xhigh、max，显式写 none 会让每次调用被接口拒绝（2026-09-25 上线时实际遇到）。固定推理强度属于策略改动，需另行评估 |
| `research_reuse_hours` | 20 | 资料未变化时沿用结论，减少重复模型调用 |
| `shadow_start_date` | `2026-09-24` | 对照账本从组合决策上线后的第一个完整交易日开始 |

## 回退

在 GitHub 上还原合并提交，Railway 自动部署回 0.14.0；本机同步回旧代码并重启。0.15.0 新增的表和云端触发器保留也不影响旧版本运行。
