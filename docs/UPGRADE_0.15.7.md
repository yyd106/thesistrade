# 升级到 0.15.7：本地监督审查

本版将监督审查从指定 Claude 改为本机通过现有 ChatGPT 订阅执行。研究、组合决策、模拟交易、每日复盘和硬性风控沿用原流程；审查只产生建议，不批准提案、不采纳研究规则、不改策略、不延长研究心跳。

## 审查什么

| 对象 | 触发 | 内容 |
|---|---|---|
| 评估批次 BATCH | 冻结的批次出现，或其作者小结变化 | 运行是否可靠、效果结论是否得到程序统计支持 |
| 完整提案 PROPOSAL | READY 提案出现，或材料/提案版本变化 | 根因、反证、检验方案、失败标准、回退和风险边界 |
| 上线后复核 FOLLOWUP | ADOPTED 提案采纳后，有新的评估批次结束 | 对照原方案检查效果；观察期或数据不足继续观察 |

调度每分钟发现一次待审事项；批次发现范围为最近 20 批，升级时也会补排这些批次。更早批次可以通过 request 明确指定。提案缺少 hypothesis、change、evidence、test_plan、failure_criteria、rollback 任一项时不调用模型，页面列出待核实原因。DRAFT 草稿不会自动审查；操作人补全并转为 READY 后排队，也可明确 request 一份完整 DRAFT。

## 独立会话与证据

每次审查最多调用两次订阅模型：

1. FACTS：新会话，只看程序生成的评估指标、行情健康和运行摘要；不提供作者小结、提案正文或上一次模型讨论。
2. REVIEW：另一新会话，给出相同事实、第一步判断、指定版本的作者小结和提案摘要，要求寻找反证。

沿用现有模型固定配置与订阅登录；不引入 API Key、付费后备服务或新模型配置。CLI 使用临时空目录、ephemeral 会话，关闭工具、网页与插件。首次调用和审查调用分别记录实际模型、提示词哈希及调用结果。同一模型仍可能有共同盲点，两次同意不算独立证据。

输入只限已授权的报告和提案摘要。不会读取公告原文、成交原始表、数据库文件内容作为模型附件，不递归读取 evidence 字段里的路径。对评估批次先核对所有程序文件与清单哈希；文件缺失、被改动、链接或超过预算时不静默截断，不调用模型。

审查结果必须覆盖证据、版本、归因、反证、检验方案、风险边界六项，并引用提供的资料编号。有效性评价只允许指向已有比较组；任一组独立样本小于 30 时，程序拒绝模型给出有效/无效的定论。30 是最低纪律，不是成功证明；市场相关性、置信区间、费用和事后资料仍需审查。

批次的 build_id 是生成时版本，报告可能含多个历史策略版本。缺少按原判断版本分组的证据时，应写证据不足。上线后观察期限沿用提案原 test_plan；当前不从自由文本中自动推断精确截止日期，而是在每个新批次做进度审查，缺乏可核验期限或结果时继续观察。

## 调度、失败与优先级

- 只在研究端或 standalone 启动，云端不调用审查模型。
- 独立单线程审查队列；采集、研究、组合决策、每日复盘等优先任务排队或运行时不启动审查。
- 后台审查进行中出现高优先级任务、离线或关闭调度时，在下一调度周期仅终止审查自己的模型进程。保留尝试，至少 5 分钟后再排，不占失败重试次数。
- 普通失败至少隔 30 分钟重试，同一版本自动最多 3 次（初次加 2 次重试）。耗尽后仍显示待审，允许人工 retry。重启时 RUNNING 恢复为待审，已保存的尝试保留。
- `supervision_enabled` 默认 true；`supervision_timeout_seconds` 默认 180，范围 60–300。均为运行类设置，不改变交易规则与策略配置指纹。代码升级仍会改变 build_id。
- 手动 run 同样在启动及两阶段之间检查研究优先级；后台调度另支持阶段内中止。不会阻挡云端执行或刷新 12 小时研究授权。

## 命令

在升级后的 `ashare-agent/` 下执行：

```sh
./agent supervision list
./agent supervision show SR-...
./agent supervision request EV-20261009-1530 --kind BATCH
./agent supervision request <提案编号> --kind PROPOSAL --batch EV-20261009-1530
./agent supervision request <已采纳提案编号> --kind FOLLOWUP --batch EV-20261009-1530
./agent supervision run SR-...
./agent supervision retry SR-...
```

list/show 只读；request/retry 只排队；run 会调用订阅模型。自动发现与执行由原本本机服务完成，无需桌面对话一直开启。

## 留痕、展示与兼容

- 新增 `supervision_reviews` 表，不改变旧表或旧账本。
- 每次尝试保存在 `workflow/supervision/<审查编号>/<尝试号-随机后缀>/`，包含 input.json、两阶段摘要输入/模型输出/元数据及 result.json。失败、中断和旧结果保留。
- 输入哈希绑定批次清单、作者小结、提案内容、采纳记录、模型配置、审查提示词与 schema 版本。材料变化后旧结果标为 STALE；新材料单独排队。
- 页面在“每日复盘”下增加“监督审查”折叠区，区分待审、审查中、待重试、已审查、建议通过、证据不足、建议驳回和等待用户批准。
- `evaluation list/show` 的 `local_review` 同时显示本地审查状态；原批次状态与外部检查字段保留其旧含义，不冒充为本地模型审批。
- 只有完整 READY 提案的有效 RECOMMEND 结果显示“等待你批准”；审查不会改变提案状态。批准和上线继续使用现有治理命令及 Dean 的明确确认。
- 摘要通过签名后的 `/api/sync/reviews` 传给云端，每分钟同步时有变化才发送。新特性 `supervision_summary` 只传展示，不写研究心跳，不改交易计划；旧云端不接收，等云端升级后恢复展示。
- 报告仓库成为可选摘要备份，新增 `supervision/summary.json`；不上传模型输入、调用日志或数据库。本地审查不依赖 GitHub 同步成功。
- 外部审查可在 `checks/<批次>.md` 头部写 reviewer、model、review_version。无头部旧文件继续按历史 Claude 记录读取；旧 `claude-check.md` 保留，新通用记录写 `review-check.md`，每版存入 check-history。历史 Claude 通知显示其原身份。

## 验收与部署

源代码分支 `feat/local-supervision-review`。按原流程由 Dean 推送并合并，先云端后本机；不在运行中的目录替换代码。测试使用合成数据库和模型替身，不向模型发送生产资料，不手动触发生产研究。

部署后只读核对：

1. doctor 与两端 /health 均为 0.15.7，代码指纹一致；服务运行。
2. `supervision list` 能读，现有批次和完整提案自动排队。研究忙时待审是预期。
3. 一个正常完成的审查有 FACTS、REVIEW 两个独立调用目录，以及输入哈希、审查版本、实际模型信息。
4. `evaluation show <批次>` 的程序文件完整性保持 OK；提案生命周期没有被审查自动改变。
5. 页面能区分证据不足与建议通过；上传审查摘要没有延长原研究授权。

回退代码时保留新表和全部审查目录；旧版本忽略新增表、字段和展示。不要删除数据或重写旧报告。
