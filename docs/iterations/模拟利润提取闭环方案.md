# 模拟利润提取闭环

状态：代码与隔离验收完成，运行部署验收另记本地笔记。Dean 于 2026-10-11 明确回复“按照你的推荐规则来”，确认本文件三项推荐规则并授权实现。原需求已确认10万元本金、严格超过阈值、15/12、20/15、30/20、40/30……万元阶梯、提取前按最新资产重算、每完成一次只前进一档。

## 本轮实现

云端识别当前档位的触发，冻结新增买入，保存估值快照和唯一周期，展示最新资产、留存目标、候选提取金额、可用现金及阻塞原因。确认前重新估值并生成不可变的计划版本。剩余候选额为max(0, 当前净资产−留存值)；当前净资产已扣除先前模拟提取，不能重复扣减累计提取额。

已初始化的执行端每60秒复核一次，提交与成交前还会在资金事务内复核；研究端只读。管理员取消后，同档等待资产先回落至阈值或以下、再重新严格越线，避免取消后立刻反复生成同档计划。

Dean以现有管理员身份确认具体周期、版本和金额。一次性回执绑定账户状态；过期或状态变化必须重新预览。云端同一事务核验、扣模拟现金、记资金流水、增加累计提取并注销对应净值份额，完成对账后才推进一档。重复确认、网络重试与重启不得重复记账；研究端只同步结果。

首版不接真实转账，也不新增自动卖股：现金不足、行情缺失、未知委托或提取后违反既有仓位约束时等待。利润提取是资金流，不计作投资亏损，不解除回撤锁定。

## 用户已确认规则

1. 触发后跌回阈值或以下，暂停尚未完成的提取，等待重新严格超过本档阈值再生成计划；管理员可取消未发生部分，已发生流水保留、不推进档位。未知结果必须先对账才能释放预留。
2. 多档跳涨只复核当前档，完成后重新估值再判断下一档。例如首档由14万跳到35万，先展示提取23万、留存12万；管理员确认后只前进到20/15档，不能拿旧35万连续触发。
3. 留存目标不设自动容差。所有与确认计划不符的差异进入人工复核，不能因接近目标就自动完成。

三项规则已由用户确认；不另设金额或百分比容差。具体模拟资金操作仍由后续管理员回执确认，开发授权不替代逐次资金操作。

## 验收场景

等于15万不触发、超过1分触发；16万提取4万；回撤后旧金额失效；已提取1万且当前资产14万时剩余候选2万但因未重新越过15万而暂停；现金不足或不可卖等待；跨档跳涨不连续提取；并发、重试、重启只记一次；旧确认、普通用户和模型均不能记账；提取前后投资损益、单位净值及风险锁不产生假变化。

部署顺序为云端先行、本机随后；旧记录保留，新周期沿用同档唯一标识。同步通过按需请求的只读摘要兼容旧节点，本机无模拟提取写入口。每次成交前的资金事务核验停买状态，已知未成交买单撤销，未知委托先对账。提取后保持现有较严的资产、总仓及组合风控约束。验收结果在测试、独立审查及两端部署后补充。

验收结果：新增55项Python测试；完整1071项测试通过（1项既有环境跳过），7组前端测试通过。覆盖三项规则、旧账接续、双连接并发、响应中断、逐分回滚、单位净值、三路线停买、60秒复核及旧节点同步兼容。既有全球部分成交止损测试将合成资金改为14万元，保留原测试目标并避免触发新提取规则。
