# 0.22.11：恢复 D14 的个股趋势门槛

0.22.10 在 D14 两端配对后，把“仓位模式已启用”同时用作“个股趋势门槛已被替代”，导致新研究和研究续期都可能遗漏 `TREND_NOT_CONFIRMED`。0.22.11 将这两个判断分开：只有已配对的 R1 保留原先替代行为；D14 在所有市场状态下都要求 MA20 > MA60 且最近完整日线收盘价 >= MA60。趋势不满足时生成 `NO_ENTRY`，其他价格、风险、模型和组合约束仍分别生效。

研究端的 R1 仍须收到 `exposure_caps_v1`；云端判断只依据已接收组合中的模式，不用本地配置代替它。D14 的 `exposure_caps_v2` 配对、50%/10%/37% 偏空限制、P06、原生配置审批和同步签名协议没有变化。本版本不需要新增配置键，也不执行成本基准重置。

新研究和真实复用续期均重新计算趋势阻断。升级不会回写既有计划，也不会因恢复入场门槛而直接平掉已有持仓；持仓退出继续使用原规则。研究行为指纹包含本次源码变化，旧版本研究不能直接作为当前版本的可复用研究。部署完成不等于已有云端组合已换新，须核对部署后的新研究及其实际接受的组合。

## 发布与验收

先部署云端，再部署研究端，核对两端版本与固定代码指纹，保留当前已审批配置。正常研究生成后，以研究实际运行时点、计划 build、已接受 bundle 和云端当前组合绑定首周期；对趋势不满足的新计划核对 `TREND_NOT_CONFIRMED`/`NO_ENTRY`。不能用升级前的计划或仅页面版本号作为修复生效证据。还需检查两端健康、心跳和错误增量。若尚无新研究或可观察的趋势失败计划，分别记录待验收，不推定通过。

代码回退会重新引入 D14 趋势缺口，因此不能把旧版作为等价安全状态。需要回退时按现有运维与交易变更流程处理，并明确首周期与旧组合仍然有效的边界。

## 验证范围

独立合成测试先在固定 0.22.10 基线复现缺陷，再覆盖 `study`、实际可复用资格检查及 `renew`、days_cash/legacy 两路、R1/D14/OFF 配对边界和云端已接收模式语义；另运行完整 Python 与前端回归。E5/E6/E7 以及第八单联合复算的入场候选都继承 `p05.entries_e3` 的趋势条件，本修复恢复该项条件的一致性，不代表生产全部成交规则或收益与回测一致，不新增收益有效性结论。
