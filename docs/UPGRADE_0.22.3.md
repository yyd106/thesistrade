# 0.22.3 · 下载中的研究策略评审与采纳记录

此前管理员下载包含数据库中的研究和组合决定，却会漏掉独立文档里已完成的外部建议评审。现在 `研究策略.md` 和 `交易策略变更.md` 开头均列出窗口内留存的评审事项：原情况、采纳或澄清内容、理由、实施状态、作用范围及下一步。`总览.md` 提供记录数量，`策略数据.json` 在 `research.strategy_reviews` 保留同一份结构化记录。四个文件名和 v1 同步协议保持兼容。

## 日期与状态

- `occurred_on` 是北京时间评审日期；`recorded_at` 是本版本真实留存时间。补录不倒填成历史时点已经存在的证据。窗口内按评审日期筛选，同时要求补录时间不晚于导出截止时刻。
- `clarified` 表示核验澄清；`accepted_pending` 表示认可方向、尚未实施；只有 `implemented` 才能填写实际实施时间。
- `production_change` 必须与已实施的研究或模拟交易规则事项一致。文档澄清或采纳方向不表示生产规则改变。
- 本记录仅供下载和审计，不注入模型输入，不修改规则、授权、持仓或订单。

## 本地记录

人工维护的 JSON 存放在数据根目录的 `workflow/strategy-changes/*.json`。每份记录使用独立编号，按 `ashare/strategy_change_log.py` 的严格 schema 写入；应先完整验证，再原子发布，补充或纠错使用新的记录编号，保留旧版证据。实际用户记录仅保存在本地数据目录，不提交代码仓库。

读取范围固定，不遍历其他文档或凭据；拒绝符号链接、非普通文件、重复编号、未知字段、非法时间和超限输入。证据只允许文档标题和 SHA256，不根据内容读取其他路径。输入错误会明确报错，不静默漏项；现有同步任务可保留上一份成功缓存。

## 验证与部署

验证评审日期及补录时间边界、状态一致性、只读导出、Markdown 转义、损坏和超限输入、固定 ZIP 文件及旧 v1 接收兼容性。发布前运行全量 Python 测试及页面脚本；先云端、再本地研究服务，确认下载包含实际留存的评审记录。
