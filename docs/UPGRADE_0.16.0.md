# 0.16.0：长期自检与策略方案生成（第一期）

Dean 于 2026-09-30 批准按可行性报告执行；按报告建议，本轮完成自动诊断与方案生成，并登记第二期所需实验设计。生产研究提示词、交易参数、资产范围、模型、风险限额均保持现行设置。

## 运行流程

1. 自选股、全球研究和组合决策登记时，在同一事务冻结判断合同；动态事件创建时冻结最初计划、方向、证据引用及版本。合同不可更新或删除。判断中原本没有的经营预测期限/量化条件标为 `UNSTRUCTURED`，不会用价格上涨证明经营结论。
2. 市场标签只读在判断时已经入库的已完成日线。固定 `trend20-vol20-v1`：最近21个收盘形成20个日收益，末收盘高于20日均值为 UP，否则 DOWN_OR_FLAT；日收益标准差至少200bps为 HIGH_VOL。全球使用资产自身序列，A股使用沪深300。少于21条、晚于判断或末日距判断超过10天时为 UNKNOWN。不按以后表现重新命名；环境标签不进入研究提示词或交易条件。
3. 每天既有 `evaluate` 任务完成评分及对照后做自检；A股休市日也运行无模型评估，以覆盖全球路线。只读取检查时已到期的结果，按路线、版本、环境、期限、行动、前向/历史来源和评分口径分组。去重、不重叠采样在分组前完成。事实、价格、组合、数据、执行分别报告；执行沿用程序复盘核验，缺证不是违规。
4. 每周既有 `weekly-report` 任务整理完整候选草稿，每周最多3个。候选目录目前包含“结构化可检验预测”和“反向证据检查”；后者至少有5个按标的去重的不重叠观察且平均超额为负才进入待验证假设。这是探索门槛，不是有效性或采纳门槛。
5. 同路线、版本、环境与具体变更合并为同一提案。新增成熟证据只追加引用，不修改原方案或已作出的批准/驳回决定；无新增成熟证据不重复登记。所有候选为 DRAFT；完整字段包括假设、变更、证据、指标、验证、失败条件、期限、回退。历史补登记及事后动态案例不触发自动策略候选。
6. 复盘原有观察按版本、标的、分类、适用环境和规范化文字跨日去重；只消除空白和标点差异，不宣称已实现语义聚类。原复盘和旧提案不回写。

## 实验设计（未运行）

每份自动候选同时登记不可修改的 `forward-design-v1`，包含现行 build、单一候选变更、同输入时点/费用/执行约束、独立账本、两个观察窗口及隔离期、未到期标签剔除、最少30对观察、最多120次模型调用/2次重试/180天等待的设计预算。预算是第二期运行器的要求，第一期实际模型调用为零。

状态只允许 DESIGNED → REJECTED/CANCELLED，所有历史保留。尚无 RUNNING/PASSED/自动发布路径，设计中的未来开始界限不等于已经开始收样；第二期启用时必须固定实际起点、基线与候选实现哈希、可用行情/费用执行适配器及检验口径，禁止补跑成“前向验证”。当前不会自动复用既有影子账本宣称候选有效。

## 命令及记录

- `./agent self-check run`：诊断，不调用模型、不产生策略变更。
- `./agent self-check propose`：诊断并按每周预算登记完整候选。
- `./agent self-check status` / `show SC-...`：最近状态与冻结报告。
- `./agent experiments list` / `show EX-...`：实验设计与历史。
- `./agent experiments register --proposal ID --file design.json`：登记一份完整不可变设计。
- `./agent experiments close EX-... --to REJECTED --note 理由`：保留原记录并关闭设计；也可用 CANCELLED。
- `./agent proposals show ID`：原方案及新增成熟证据/复盘观察。

自检只在本机研究端运行；云端不会生成策略方案。原研究任务、订阅及网络恢复流程不变。日报和周报展示最近自检记录。自检报告位于 `workflow/selfcheck/SC-....json/.md`，内容寻址，相同证据重跑不新增报告；写文件中断可从冻结数据库记录恢复。诊断读取最近180天判断，较早的合同、报告、提案和失败设计全部保留，不删除。仅新增表，旧程序回退无需恢复数据库。

历史合同标为 LEGACY，缺原始动态 build 则 UNKNOWN；不补造当时市场标签。旧输出尚缺少规范化经营预测条件时，只能显示可检验性不足。本轮不会改变研究输出格式；该修改由完整候选在后续实验中检验。
