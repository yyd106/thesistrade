# 0.22.5：组合决定审计与报告统计口径

## 授权与问题

2026-10-24 用户授权修复近两周报告经核查确实存在的问题，并提供可转交专家的处理说明。工程问题编号为 `f110c5dc1702710b998c0e40`。本轮补齐组合决定的程序审计摘要和报告解释，不改变研究提示词、模型输入、主动动作选择、目标仓位算法、交易风控或审批机制。

## 本轮交付

- 将组合评估轮次、标的决定项、动作变化率和新增资格分别统计；明确重复评估不等于独立机会，理由字段变化不等于研究新增价值。
- 说明现有研究资格、模型组合判断、发布校验与执行门槛的关系。没有确定性动作或定仓公式的部分明确标注，不能从自然语言推测不存在的规则。
- 新决定追加模型判断时点与发布时点的最小审计摘要，保留原动作、原目标、发布结果和程序调整原因。原模型输入、既有字段和交易行为保持兼容；旧决定不回填。
- 区分主动目标仓位与 HOLD/PAUSE 的当前持仓占比；报告分别展示结构化数值、原始理由和可复核范围。
- 研究指导的当前适用、历史留存、窗口新增分开计数，与程序交易规则分开说明。
- 冻结缺口区分窗口、比较基线、机制前遗留与机制后缺口；同时核对逐标的来源，不用“有冻结记录”替代来源完整性。

ZIP 仍为四个固定文件，报告仍仅供管理员下载。新增审计信息遵守导出白名单和访客权限边界。

导出JSON将完整发布审计集中保存于 `coverage.publication_audits[决定编号]`，组合的 `payload.publication_audit_ref` 指向自身编号；生产记录仍保留内嵌审计。集中布局减少重复字段交错导致的压缩开销，历史内容完整保留，四文件及JSON顶层协议不变。报告读取兼容旧内嵌格式，校验引用身份、缺失与冲突；96MB解压及14.5MB压缩上限不变。

## 明确保留的限制

本轮不为提高交易次数强制产生 ALLOW，不凭一个减仓过程制定通用定仓公式，不自动批准研究指导，也不以当前资料补写早期冻结历史。主动模型目标的经济依据仍需独立研究与前向验证；保存原目标及校验过程不等于已能唯一推导目标。

## 验收与发布

专项验证覆盖混合新旧决定、价格变化导致的发布调整、主动目标与估值漂移、零规则与规则退役、冻结来源缺失/错配、旧同步包兼容以及访客字段隔离。按运行手册完成全量 Python 与 UI 检查，先云端、后本机发布，验证版本、代码指纹和同步状态。具体结果记录在本轮交付说明中。
