# 0.17.3：提案证据与监督展示

自动候选原先用对象保存 `evidence`，而监督入口只接受字符串；完整候选转为 READY 后仍会报“提案检验方案不完整”。本版规范化两种证据格式，并在交易与复盘中集中展示提案及审查状态。

## 用户可见变化

- 打开「交易与复盘 → 改进提案」，查看具体改动、假设、证据摘要、反向解释、检验方案、失败标准与回退方式。
- 提案状态与监督状态分开展示：DRAFT 是草稿，READY 是等待审查或决定，监督建议通过仍需 Dean 明确批准；旧材料的审查显示已过期。
- 自检证据使用冻结程序统计，说明路线、版本、期限、历史/前向来源、样本数与时间簇数；判断引用数不称为独立样本数。实验 DESIGNED 明确表示只登记设计、尚未运行。
- `./agent proposals show <编号>` 增加同一份 `review_card` 摘要，并可按编号查询较早提案。
- 卡片优先显示待审方案、草稿及已批准/上线方案；超过展示数量或字节预算的历史记录继续通过本机命令查询。

## 证据与审查版本

原有文本证据保持兼容；自检对象须符合已知结构，且引用冻结记录。缺失或错配引用不能伪装成有效证据。摘要不沿 evidence 路径打开文件，不读取原始资料或研究正文。新增成熟证据作为新监督材料的一部分，旧记录保留，当前性由材料哈希检查。

网页只接收允许的提案摘要与程序统计，通过既有签名监督摘要接口同步；摘要总量受现有 1 MB 接收上限约束。展示更新不续研究心跳、不改变账本、提案审批状态或交易资格。

## 范围与验证

本轮对应工程问题 `20b0580d1758896540d422ed`。研究提示词、模型、评分期限、交易规则和风险限额保持当前实现；无自动批准、自动修复、5 日评分或前向实验执行。

验证覆盖自动候选进入两阶段监督、旧文本兼容、缺失/恶意结构、材料追加后失效、只读展示、历史编号查询、摘要字节上限、签名同步不续心跳，以及页面状态与不可信文本。完整测试和两端上线结果记录在本地部署笔记。
