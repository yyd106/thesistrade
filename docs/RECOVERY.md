# 失败项、自动补齐与交易限制

适用版本：0.3.2。工作台：http://127.0.0.1:8765/ 。当前执行范围仍为本地独立模拟；EMT 的账户查询与这里的账本分开。

## 当天失败与其他卡点统一归口

首页“待办与卡点”集中呈现资料失败、研究限制、任务未完成、盘面条件和已知程序能力缺口。每项都有原因、交易影响、处理方、下一步、最早检查/安排时间或继续条件、完成标准、相关原文。故障恢复与允许买入分别核对。

处理方分为系统、你、程序维护、系统跟踪披露、系统跟踪行情。需要你提供材料或需要程序维护的事项优先提示；价格或业绩条件不满足不是故障，不要求反复下载报告。当前科创板执行规则未实现，会明确列入程序维护，不掩藏在其他资料缺口后面。

额外补齐次数用完后，会转为后续处理方案：保留对应原因和原文、提供补充材料的路径、指出下一次定时研究或下一交易日补齐的最早安排。现有定时研究仍继续；登录、额度、许可、OCR、程序能力缺口分别给出明确动作。程序维护待办不会被冒充为已经启动的自动开发任务。

调度器每60秒核对清单，不为此额外调用大模型。实际执行仍由原有采集、研究、盘面和复盘任务完成。所列时间是最早安排，其他任务在运行时会排队；只有排队不算恢复。关闭网页不影响检查；Mac休眠或服务异常时页面提示清单未更新，不伪造已执行。

当天失败按股票、来源、具体资料归并，显示已恢复和未恢复；当天未完成任务另列，避免把同一故障的模型尝试和任务重复计数。公共失败只列一次，同次盘面模型失败合并涉及股票。未解决项跨日、重启保留，同项恢复后从当前清单移除，原错误与每日记录保留；再次失败会重新打开。

每日清单保存于 `/Users/dean/Documents/Codex/Agents/ashare-data/workflow/followups/YYYY-MM-DD.json`，日期为北京时间。当天文件持续更新；以前的文件保留最后一次真实核对时间，不声称是休眠期间的完整监测。SQLite也保存当前事项、首次记录时间、再次出现次数和每日汇总。首页可查看当前日及前一个有记录日期，更多历史可查上述目录。

## 先看哪里

每只股票的“当前交易限制”说明为什么不能新增买入、在等什么、原文在哪里、你能做什么以及解除条件。“资料补齐进度”说明当前自动处理状态，并提供只处理该股票的“补齐资料并重研”。底部“失败项 → 处理办法”解释错误、交易影响和下一步。

失败项只在同一股票、同一步骤、同一资料后续成功时消失；其他文件成功不会掩盖它。补齐资料、研究成功、允许买入是三件不同的事。任何单项通过后，价格、资金、交易时间等其他条件仍需满足。

## 自动恢复安排

| 情况 | 系统处理 | 你需要做什么 |
| --- | --- | --- |
| 最新报价失败 | 连续竞价时段独立尝试每30秒批量刷新；没有90秒内有效报价时暂停买入和卖出 | 持续失败时按错误提示检查网络；当前仍是公开研究行情，不是EMT行情 |
| 盘中公告检查失败 | 独立尝试每120秒检查，各股票并发获取；必须有该股完整且最近180秒内的成功检查 | 一般先等下一次刷新；若仍失败，查看对应来源是否能打开、用另一网络作对照 |
| 新的重要资料尚未研究 | 自动补取关键正文，增量读取关键章节；成功后才推进已读进度 | 可等后台处理，或点击本股票“补齐资料并重研”；已有正文不需重复下载 |
| 日线、财务或关键正文缺失 | 针对本股票补取，再生成新研究 | 查看具体原文链接；持续缺失可按下方方法导入文件。日线和财务字段仍须由对应采集与核验模块取得，导入PDF不能替代它们 |
| 单次研究失败 | 每个任务最多尝试2次，每次保留独立记录；旧的有效计划保留 | 连续失败按具体错误处理。登录/额度问题暂停重复尝试，恢复后在运行详情中“继续研究已有资料” |
| 普通背景新闻、一般参考资料、复盘失败 | 保留失败记录，不因此单独禁止买卖 | 普通资料等下次采集；复盘可点击“更新复盘” |
| 盘面模型超时 | 精简输入，只调用有可能买入的候选；确定性等待与止损/止盈检查不需要模型重复判断 | 无需先增加模型线程。迟到的买入建议不执行，下一Slot重新判断 |

采集线程与模型线程分开。请求未结束时不再叠加同类请求；网络慢时实际间隔可能大于配置值。公告来源不可用会暂停新增买入，但不直接阻止按既定条件减仓。减仓仍要求有效报价、可卖数量、交易时间及有效退出计划。

交易日08:00至22:00，每15分钟最多安排一只股票自动补齐；每只股票每天最多2次自动补齐任务，按已尝试次数轮转。任务重启不重置每日上限。达到上限会显示下一步，可手动处理；下一交易日重新检查。00:00/06:00/12:00/18:00的六小时采集研究独立运行，不计入上述“补齐”计数。手动研究也计入订阅用量。

这些措施减少暂时故障造成的中断，不能保证任何失败都不影响交易。旧计划不会被延长有效期；过期报价、未知重大风险不会被当作已经通过。

## 事项核验与自动解除

按 Dean 确认的方式：证据与规则通过后自动解除该事项；无法核验时列出缺口和所需材料，不要求逐次人工批准。

第一版已支持一种可明确验证的情形：巨潮原始“权益分派实施/分红派息实施公告”中的纯现金分红。核对证券代码、唯一税前每股现金金额、登记日、除息日、明确不送股不转增、实施日期、至少60个完整日线及登记日策略持仓。已核验的现金分红用于调整除息前收盘价，重新计算可比均线；原始行情、原文哈希、证据位置和规则版本保留。

以下情况仍会给出具体缺口：只有预案/标题/摘要；更正或多版本冲突；送股、转增、配股、差异化分红；公告金额或日期不明确；策略登记日持股但现金分红尚未记账。最后一种需要补充账务处理，不能靠你再次下载同一PDF解决。

诉讼、调查等重大风险不能仅凭“已经读过”或模型说“没事”解除。需要对应事项的最新正式进展/结论原文，核对剩余赔偿、冻结、处罚、经营影响等。当前尚无这类事件的通用自动结案规则；如缺规则，界面会保留限制，需要针对该事件补充规则与验证，不会承诺补一个文件即可放行。

在“事项核验记录”中可看已通过或未通过、缺什么、核验字段及原文。事件核验通过不会跳过重要正文阅读、研究否决或价格趋势条件。

## 手工补充报告的具体步骤

1. 从“查看具体资料”打开巨潮或公司原文，下载可选中文字的PDF。不要把网页错误页改名为PDF。扫描件先做OCR并核对数字；系统目前没有自动OCR。
2. 放到 `/Users/dean/Documents/Codex/Agents/ashare-data/inbox/`。也支持UTF-8的TXT/MD；文件不超过20MB。
3. 同目录新建一个JSON文件，示例如下。文件名、标题、证券代码、发布时间和原文网址必须换成实际值；网址使用该资料的原始链接，以便关联原先缺失的正文。

```json
{
  "file": "report.pdf",
  "symbol": "sz002415",
  "kind": "company_report",
  "title": "这里填写报告原始标题",
  "published_at": "2026-09-18T08:00:00+08:00",
  "source_url": "https://static.cninfo.com.cn/finalpage/实际原文路径.PDF",
  "cloud_allowed": true
}
```

`kind` 可为 `company_report`（公司公告）、`broker_report`（券商研报）、`news`（新闻）。`cloud_allowed: true` 表示你允许正文通过现有订阅送到云端研究；只对可这样使用的资料设置。未授权的资料可存本机，但不能声称已完成模型阅读。

4. 点击该股票“补齐资料并重研”，或运行详情中的“仅补取资料”，再继续研究。导入失败会显示文件名和原因。导入原文可以填补阅读缺口，但不会冒充自动下载成功，也不会把手工导入标成已经核对过来源的巨潮公告；因此分红自动核验仍要求成功取得官方原文。

## EMT行情：需要你确认的唯一接口信息

官方FAQ说明：部分最新行情查询通常有1至3秒延迟，查询结果不等于实时订阅；实时行情应使用订阅，仿真只支持L1。因此接口能力可以支持10/30秒观察，但你已经成功的交易登录和资金查询不能证明行情权限已开通。

请通过EMT官方支持确认以下内容（不需要把密码写入项目或发到聊天）：

> 我已开通普通仿真交易API。请确认是否包含L1行情，提供行情登录地址和端口、是否复用交易账号，以及是否支持沪深股票（含科创板）的实时快照订阅。请同时说明订阅数量与调用频率限制。

拿到行情端点和权限说明后才能实际验证该账号的行情接入；当前版本没有猜测交易端口就是行情端口，也没有接入EMT行情。公开报价持续正常与EMT权限是两项独立事实。

来源：[EMT官方FAQ，Q27/Q31/Q35](https://emt.eastmoneysec.com/api/help/md_input_2EMTAPI__FAQ.html)、[QuoteApi文档](https://emt.eastmoneysec.com/api/help/classEMQ_1_1API_1_1QuoteApi.html)。

## 本地配置

普通设置文件：`/Users/dean/Documents/Codex/Agents/ashare-agent/config.json`。下列值已有默认值，无需为了启用本轮功能手动填写；如需调整，把对应键合并进现有JSON，不要覆盖其余配置。

```json
{
  "background_market_enabled": true,
  "quote_poll_seconds": 30,
  "announcement_poll_seconds": 120,
  "announcement_max_age_seconds": 180,
  "research_attempts": 2,
  "recovery_interval_seconds": 900,
  "recovery_daily_limit": 2
}
```

行情尝试间隔支持10至60秒；默认选30秒。改成10秒只改变请求安排，不能改变上游延迟或保证服务可用。研究重试支持1至2次。运行依赖Mac开机、登录、联网且未休眠；本轮未改变你的系统电源设置，也未新增付费API。
