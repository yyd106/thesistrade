# 升级到 0.15.6

0.15.6 做四件事：

1. 行情加备用接口，中断只记录、不打扰 Dean；
2. 评估改为按编号的批次：Dean 随时可以要一批，程序每 5 个交易日自动生成一批；
3. 给 Dean 的网页弹窗通知，只用于需要他决定、可以否决或必须知道的事项；
4. 私有报告仓库：本机把日报和评估批次推给 Claude 检查，Claude 的通知和检查结论从同一个仓库回来。

交易规则、研究提示词、模型、策略类设置和硬性风控都不变。

## 改了什么

### 行情备用接口与中断记录

- **主接口不变**：腾讯批量报价 `qt.gtimg.cn`。它返回的有效报价立即入库，不等备用接口。
- **备用接口**：某只股票没有可用报价时，改从腾讯分时接口 `web.ifzq.gtimg.cn` 取这一只的最新价。没有可用报价包括四种情况：
  - 整批请求失败；
  - 返回里缺这只；
  - 字段不对；
  - 连续竞价开始两分钟之后（9:32–11:30、13:02–14:57），某个交易所的股票里最新的一条报价也超过 90 秒（这个交易所的行情停止更新）。沪深两边各有 3 只以上股票时分交易所判断，否则按整批判断。只有个别股票的报价旧，说明是这只股票没有成交，照常入库，不算中断。
- **备用接口的限制**：
  - 每只股票每分钟最多问一次，上次成功与否都一样。云端两个刷新任务不会重复询问同一只；另一个任务正在问的股票，这一轮按没有报价计。报价有效期仍是 90 秒。
  - 几只股票同时缺报价时，最多 4 个并发请求，全部请求合计最多等 20 秒。
  - 分时接口给出的最新价必须在前收盘价上下 21% 以内，否则拒绝使用。这是为了防止字段位置读错，被当成成交价。
  - 停牌股票（价格为 0）不算中断，也不问备用接口。
- **两个接口都属于腾讯**：备用接口防的是一个接口故障或格式变化，防不了腾讯整体封禁服务器地址。
- **没有采用的来源**：
  - 东方财富 `push2` 行情接口、雅虎 `query1`：robots.txt 禁止程序抓取；
  - 新浪行情：要伪造浏览器来源（Referer）才能访问。
- **每次中断记为一个事件**，由执行端（云端）写入 `quote_health` 表，分两类：
  - `PRIMARY_DOWN`：主接口没有给出可用报价（备用接口开启时，改用分时接口）；
  - `NO_QUOTE`：两个接口都没有可用报价。这段时间不会买入，持仓也无法按止损卖出。
- **事件的起止**：行情只在连续竞价时刷新。超过 5 分钟没有刷新（午休、收盘、重启）时，事件在最后一次刷新处结束，休市时间不计入中断。午休和收盘后几分钟内，程序会把这样的事件结束掉并做下面的核对。
- **持仓股票单独计时**：每只持仓股票只记它自己没有报价的那几段。别的股票断了很久、它只缺一次，不会把整段中断算到它头上。
- **中断期间的止损核对**：一只持仓股票没有报价的那一段结束后，排进核对队列。行情监控每分钟单独处理一次队列，不占用报价刷新；同一只股票每分钟最多请求一次分时数据，排队的几段一起核对。核对这一段里：
  - 最低价是否触及成本止损价或计划止损价（与盘中止损用同一条不等式）；
  - 最高价是否到过计划退出价。

  核对结果只记录，不补单，也不倒填成交。服务在收盘时没有运行、第二天才结束的中断，分时数据已无法补查，记为无法核对。
- **分钟数的算法**：各事件的秒数先相加再换算成分钟，所以很多次短暂中断也会累计起来。持仓无报价的分钟数，按至少一只持仓股票没有报价的时间计算。
- **中断记录在哪里看**：事件随账本同步到本机。本机请求时才附带，只放在最后一页，按云端写入时间增量同步，最多回溯 8 天。记录出现在三处：
  - 日报新增“行情源”一节；
  - 日报“需要关注”新增五条规则：
    - 持仓无报价达到 5 分钟；
    - 自选股累计无报价达到 30 分钟；
    - 中断期间触及止损价；
    - 主接口累计 30 分钟没有可用报价；
    - 中断记录或通知没能同步到本机；
  - 评估批次的 `quotes-health.json`。
- 中断记录或通知同步出错时（本机导入出错，或云端生成出错），只跳过这一部分，账本照常同步；日报“需要关注”写明哪一部分没有同步到本机。
- **不给 Dean 发告警**。是否需要购买稳定的付费行情，由桌面 agent 和 Claude 看日报和评估批次判断。判断需要购买时，才用网页通知请 Dean 决定（见下文）。
- 新设置 `quote_fallback_enabled`，属运行类，默认开启。

### 评估批次

一个批次把一段时间里程序记录的材料打包，并给出编号。桌面 agent 写小结、Claude 做检查，读的是同一份材料。

- **编号**：`EV-YYYYMMDD-HHMM`，取生成时的北京时间，例如 `EV-20261009-1530`。
- **覆盖区间**：从上一批的生成时间到这一批的生成时间。第一批覆盖最近 7 天。
- **交易日**：按收盘计算，北京时间 15:00 收盘之后当天才算一个交易日。休市日和周末调休上班日都不算。
- **批次目录**：`ashare-data/workflow/evaluations/<编号>/`。以下文件都由程序生成，不调用模型：

  | 文件 | 内容 |
  |---|---|
  | `report.md`、`report.json` | 本期评估：结论注册表、对照账本、版本变化、模型调用、未关闭的工程问题和提案（周报的格式，按本期区间） |
  | `digests.md` | 区间内逐日日报汇总：每天一行，列出全部“需要关注” |
  | `governance.json` | 区间内的设置修改、提案、研究规则和工程问题 |
  | `quotes-health.json` | 区间内的行情中断、无报价分钟数和中断期间的止损核对 |
  | `notices.json` | 区间内给 Dean 的通知，以及仍未处理的通知 |
  | `manifest.json` | 编号、触发方式、区间、交易日列表、版本、build，以及上面每个文件的 SHA-256 |

  之后可以添加，但不改动上面的文件：
  - `notes.md`：桌面 agent 的小结（`./agent evaluation note`）；
  - `claude-check.md`：Claude 的检查结论，从报告仓库导入。
- **手动生成**：`./agent evaluation start`。
  - 距离上一批收盘的交易日不足 3 个时，返回 `TOO_SOON` 和一句说明，什么也不生成。样本太少的批次看不出变化。
  - 确实需要时加 `--force`，批次清单会注明 `forced`。
  - 设置 `evaluation_min_trading_days`，运行类，默认 3，范围 1–10。
- **自动生成**：每天 23:50 日报之后检查一次，距离上一批已收盘 5 个交易日就自动生成一批。设置 `evaluation_auto_trading_days`，运行类，默认 5，范围 0–20，填 0 关闭自动生成。手动和自动不会同时生成：是否到期在加锁之后才判断。
- **其他命令**：
  - `./agent evaluation list`：列出批次，以及是否有小结、是否有 Claude 的检查；
  - `./agent evaluation show <编号>`：批次信息，并按清单逐个核对文件的 SHA-256（`OK` / `CHANGED` / `MISSING`）；
  - `./agent evaluation note <编号> --file 小结.md`：写入桌面 agent 的小结。已有小结时，加 `--replace` 才替换。
- 周报（每周六 10:00）和 `./agent weekly-report` 照旧生成。

### 给 Dean 的网页通知

只有需要 Dean 本人处理的事项才弹窗，范围按授权书：

| 类型 | 用途 | 网页上的按钮 |
|---|---|---|
| `DECISION` | 需要他决定，例如购买付费数据源，或授权书第三类事项 | 批准 / 不批准 / 稍后再看（批准和不批准都要再点一次确认） |
| `VETO` | 授权书第二类改动上线前的通知，可以否决 | 否决这项改动 / 不否决 / 稍后再看（否决要再点一次确认） |
| `INFO` | 必须知道、不需要操作，例如回撤 25% 触发风控 | 我知道了 / 稍后再看 |

- **在哪里弹**：云端网页，管理员登录后，一次弹一条，最早的先弹。
  - Guest 看不到通知，也不能处理；
  - 研究端本机网页不弹，通知送到云端后在云端处理；
  - 独立运行（standalone）的节点在本机网页弹。
- **谁发通知**：
  - 桌面 agent：`./agent notices new --kind DECISION --title "…" --body-file 正文.md [--deadline 2026-10-12T12:00:00+08:00]`；
  - Claude：在报告仓库写 `notices/outbox/*.md`，本机同步时导入；
  - 程序：回撤触发 25% 风控时，执行端自动发一条 `INFO`。
- **怎么送达**：
  - 研究端写的通知，每分钟随云端同步送达；
  - 云端自己发的通知（回撤风控），随每分钟的账本同步回到研究端；
  - Dean 在网页上的答复（批准、不批准、否决、已知悉，以及答复人）也随账本同步回到研究端；
  - `./agent notices list` 查看全部通知和答复。
- **弹窗的行为**：打开时焦点在标题上，不在按钮上，免得正在别处打字时误按回车；弹窗显示的那条没处理完之前，不会被新到的通知换掉；答复过的通知不会再弹出。
- **答复只是记录**：程序不会因为“批准”自动执行任何事。批准后的实施仍按授权书，由 Claude 或 agent 去做。付费购买由 Dean 本人操作。
- **不可改写**：通知送达云端后正文不能再改，已答复的通知不能改成另一个答复。

### 私有报告仓库

本机把程序生成的页面推送到一个私有 GitHub 仓库，Claude 在那里检查批次。仓库只有这些内容：

| 目录 | 写入方 | 内容 |
|---|---|---|
| `digests/` | 本机 | 每日运行日报：推送最近 120 天的；更早的留在仓库里，不再更新 |
| `weekly/` | 本机 | 周度评估报告 |
| `evaluations/<编号>/` | 本机 | 评估批次：清单列出的文件、`manifest.json` 和 `notes.md` |
| `notices/state.json` | 本机 | 全部通知和 Dean 的答复 |
| `notices/outbox/*.md` | Claude | 给 Dean 的新通知，本机导入后在网页弹窗 |
| `checks/<编号>.md` | Claude | Claude 对该批次的检查结论，本机导入后放进批次目录，批次状态改为 `CHECKED` |

- **不上传的内容**：数据库、原始资料、设置文件和密钥都不会上传。仓库里的内容也不会被执行；代码更新仍走原来的代码仓库和部署流程。
- **不能越出仓库**：仓库里的链接一律当作普通文件取出，程序也不通过链接读写任何路径，所以提交到仓库的内容碰不到本机其他文件。导入的通知和检查文件只接受普通文件，单个最大 200 KB。本机负责的路径（日报、周报、批次、`notices/` 目录、`README.md`）如果被提交成链接或子模块，或目录位置被放了文件，同步时删掉重写；`notices/outbox/` 里的链接和子模块也会被删掉，Claude 写的普通通知文件不受影响。
- **单个文件上限**：超过 1 MB 的页面不上传，同步结果里列为 `skipped`。
- **频率**：本机服务每小时同步一次；日报生成后、新批次生成后，以及写入批次小结后，还会各触发一次。
- **命令**：
  - `./agent reports sync`：立即同步；
  - `./agent reports status`：设置、公钥和上次同步结果（含导入失败的文件和原因）。
- **权限**：
  - 本机用只属于这个仓库的部署密钥（ed25519，私钥保存在 `ashare-data/secrets/`，权限 600）；
  - GitHub 主机公钥固定写在程序里，不用首次连接时自动信任；
  - git 忽略用户自己的全局设置，不会用到 Dean 的 GitHub 登录；
  - 网络挡住 22 端口时，自动改用 GitHub 的 443 端口；
  - 推送被拒绝时同步报错（例如部署密钥没有写权限），不会显示成功。
- **容量**：日报每天约 10 KB，每个批次约 0.1–0.3 MB，一年不到 50 MB，远低于 GitHub 建议的单仓库 10 GB。个人仓库不需要 SSO。
- **设置**：
  - `./agent reports setup --remote git@github.com:<owner>/<repo>.git` 生成密钥，并写入 `reports_remote`，打开 `reports_sync_enabled`；
  - `reports_remote` 只能由这条命令写入，`./agent config set` 不能修改。

## 兼容性与部署顺序

- **数据库**：新增三张表 `quote_health`、`notices`、`evaluation_batches`，启动时自动建立；原有表不变。
- **同步协议**：
  - 云端多通告两个特性标记 `quote_health`、`notices`，并新增 `/api/sync/notices` 接口；
  - 账本请求多一个可选字段 `extras`；
  - 旧本机不发 `extras`，也不调用新接口；
  - 旧云端忽略 `extras`；本机看不到 `notices` 特性时，不发送通知。
- **部署顺序**：先云端，后本机。
- **代码指纹变化**：升级后第一轮研究全部重新调用模型。
- **合并时间**：Railway 部署会重启云端，所以在交易时间以外合并（北京时间 15:30 以后或 9:00 以前）。

## 已知限制

- 两个行情接口同属腾讯，腾讯整体封禁时仍会中断。中断记录是判断是否购买付费行情的依据。
- 中断期间的止损核对只记录，不补单，并且依赖腾讯分时数据。服务在收盘时没有运行、第二天才结束的中断，无法补查。
- 授权书第二类改动的自动上线机制尚未实现：`VETO` 通知目前只记录否决，不会自动撤回改动。下一版实现。
- 报告仓库要求本机能通过 SSH 访问 GitHub。
- 批次生成后不再改动；生成之后才补到的记录不会回填进这一批。
- 中断期间的止损核对，如果在取出之后、写入结果之前遇到服务重启，或数据库被占用超过 20 秒，这一段会丢掉核对：日报和批次里这段没有核对记录，看起来和“核对过、没有触及”一样。持仓无报价的分钟数照常统计和提示。下一版改为写入失败时放回队列。
- 报告仓库里如果出现不是 UTF-8 的文件名，本机（macOS 的文件系统不接受这种文件名）每次同步都会失败，直到把这个文件从仓库删掉；`./agent reports status` 会显示失败原因。Claude 写入的文件名只用英文字母、数字和连字符，扩展名为 `.md`。
